# 0.7.0: ccPet on Rust

**Goal:** the pet uses less memory and disk, and starts faster. It does the same things as 0.6.x: no feature changes, no new features until this is done.

## Starting point (measured 2026-11-18, 0.6.8)

| What | Now |
|---|---|
| Windows app (Electron, 4 processes) | 279 MB private memory, 409 MB working set |
| Installer / installed | 86 MB / 280 MB |
| WSL bridge (Node) | 105 MB |
| Mailbox waiter, one per open Claude Code session (Node, `pet-hook.mjs wait`) | ~65 MB each; 7 running = ~450 MB |
| Each hook event (Node start) | a new Node process per event |

The biggest waste is in WSL: one 65 MB Node process per session just to wait for a message, plus a Node process started for every hook event.

## Approach

Rewrite the parts that run in the background in Rust. Move the window to **Tauri** (Rust instead of Electron). The pet's interface (HTML, CSS, TypeScript in `ui/src/renderer`) stays: Tauri shows it in the system web view (WebView2 on Windows, WebKit on macOS and Linux), so it is not rewritten.

Rejected: rewriting the interface in a Rust UI library (egui, Slint, Iced). That means weeks of work to redraw what already works, and a transparent always-on-top sprite window is harder there than in a web view.

## Phases (each ends with tests passing and the pet working; committed one by one)

1. **`ccpet-hook` in Rust** (replaces `hook/pet-hook.mjs`, `hook/pet-statusline.mjs` and the `wait` of `pet-helper.exe`). One small binary per platform. Hook settings point at it; old settings keep working until re-applied. Expected: waiter ~65 MB → ~1–2 MB; a hook event starts in milliseconds. *2–3 days.*
2. **Bridge in Rust** (`daemon/src`, ~2,200 lines + tests): sessions, hooks over HTTP and the socket, mailbox, transcripts, limits, PTY send, hook installation with diffs and backups. Same JSON-lines protocol to the window, so the Electron app keeps working with it. No Node.js needed inside WSL any more. Expected: 105 MB → ~5–10 MB. *4–6 days.*
3. **Tauri instead of Electron** (`ui/src/main.ts` and friends, ~3,000 lines): window, tray, global hotkeys (incl. Ctrl+Alt+1…9), autostart, always-on-top over players and games, click-through, Windows desktop-app sending (`pet-helper.exe` stays as is), update check. Agent SDK chats (TypeScript only) go through the `claude` CLI instead. Expected: installer 86 MB → ~10–15 MB, memory ~280 MB → ~80–120 MB. **Risk:** transparent windows on Linux (WebKitGTK) are less reliable than in Electron. *5–8 days.*
4. **Builds and checks**: Windows, macOS (arm64, x64), Linux (deb, AppImage) in CI; the smoke test; measuring again against the table above; 0.7.0 release. *3–5 days.*

**Total: about 2.5–4 weeks.** Phases 1 and 2 already give most of the memory gain and can go out as 0.7.0-beta if wanted.

## Tools needed

- Rust in WSL (`rustup`, about 1.5 GB in the home folder): phases 1–2.
- Windows builds: either Visual Studio Build Tools (C++ workload, about 6 GB) for local builds and testing, or Windows builds only in GitHub Actions (nothing installed, but every Windows test waits for CI).

Hook tests run against it with `PET_HOOK_BIN=<binary>`.

**Phase 2: code complete, not yet run against a real `claude` (committed on `v0.3-dev`).** `native/ccpet-core/src/`: `types`, `i18n`, `map_event`, `store`, `mailbox`, `soft_stop`, `summary`, `paths`, `transcript`, `usage`, `install` (hooks, waiter, statusLine, diffs, `.bak`; native `ccpet-hook` only, 0.6 Node entries are recognised and replaced), `procinfo`, `pty_send`, `adopt`, `hook_socket`, `hook_http` (tiny std HTTP/1.1 server), `bridge` (commands, hooks, permissions/questions, mailbox send, PTY send, interrupt watch, usage push), `claude_proc` (stream-json process + control requests: the protocol was read from the Agent SDK's `sdk.mjs`), `live_usage` (`get_usage` on a ring click only), `runner` (new chats, resume fallback with the copy refusal, `/btw`, models, permission policy). `native/ccpet-bridge/src/main.rs` wires it all. 51 Rust tests (the claude parts run against a fake `claude` in python3) + 578 JS tests pass.

**App switch-over done:** `scripts/build-native.mjs` builds `ccpet-hook` and `ccpet-bridge` into `build/hook/` (shipped as `resources/hook`); `wslHost.ts` / `bridgeLaunch.ts` run the binary when it answers `--version`, else fall back to the Node bridge (`CLAUDE_PET_NATIVE_BRIDGE=0` forces Node). The Node bridge stays until phase 4.

**Verified against the real `claude` (2026-11-18, Haiku, a separate bridge with `CLAUDE_PET_DIR`/`CLAUDE_PET_SOCK`/port 47992 next to the owner's running one):** new chat (`started`, streamed answer, `end`), follow-up into the same process, `/btw` note, model list, a real permission prompt (`touch` → pending card → allow → file created → answer), ring click (`get_usage`: `source: live`, plan, 5 h %), `release`, exit on stdin EOF. Found and fixed during it: child `claude` processes inherited `PET_PTY_SOCK` (stripped now). Note: `echo` is auto-allowed by Claude Code, so it never reaches the pet as a permission prompt.

**Installed as 0.7.0-beta.2 (2026-11-18), measured:** WSL bridge `ccpet-bridge` 1.2 MB RSS (Node bridge before: 98 MB), listening on 47822 with the waiters connected; `ccpet-hook wait` 0.5 MB each (Node waiter: 65 MB each; the old ones of sessions started before the hook upgrade stay until those sessions re-arm or end). Windows app unchanged (Electron, 4 processes, 270 MB private / 435 MB working set): that is phase 3. Installer 87 MB.

Not ported: soft stop (Windows host only); SIGTERM leaves `hook.sock` (replaced on next start); the SIGTERM→SIGKILL step of `close()` has no test. Behaviour change vs 0.6: pet chats get Claude Code's default system prompt (the SDK sent an empty one). The Windows host (`ui/src/hub/windowsHost.ts`) keeps the TS modules until phase 3. **Next: phase 3 (Tauri).**

**Build notes.** WSL has no C compiler and no sudo: build with Windows' cargo from WSL:
`cmd.exe /c "cd /d C:\ClaudePet-v2\native && set CARGO_TARGET_DIR=%LOCALAPPDATA%\ccpet-target&& %USERPROFILE%\.cargo\bin\cargo.exe build --release --target x86_64-unknown-linux-musl"`
(rust-lld + musl, see `native/.cargo/config.toml`). Run the test binaries from WSL (they land under `%LOCALAPPDATA%\ccpet-target\x86_64-unknown-linux-musl\release`). JS: `node node_modules/vitest/vitest.mjs run`, `node node_modules/typescript/bin/tsc --noEmit -p .` (3 old loadPet.test errors are known). Installer: `PATH=$HOME/.local/node/bin:$PATH npm run dist`.

## Phase 3 plan (2026-11-19)

**Toolchain:** VS 2022 Build Tools (MSVC 14.44) and Windows SDK 10.0.26100 are already installed, so the Tauri app builds locally with Windows cargo (`x86_64-pc-windows-msvc`).

**Shape:**
- **Crate.** `native/app/` is its own cargo workspace (`ccpet-app`, Tauri 2). This keeps the musl `cargo build` of `native/` unaffected.
- **Renderer.** It stays as it is (`ui/dist`: `index.html`, `renderer.js`, `styles.css`).
- **Shim.** `native/app/src/pet-host.js` is injected as an initialization script and implements the same `window.petHost` that `ui/src/preload.cjs` exposes, over Tauri `invoke` and events. The renderer needs no changes.
- **Rust main.** It replaces `ui/src/main.ts` and `ui/src/hub/*`, piece by piece.
- **Electron stays.** The Electron app keeps working and shipping until the Tauri app reaches parity: the switch happens in M5.

**Milestones** (each one is committed, and existing tests pass):
- **M1 skeleton.**
  - Window: transparent, frameless, always on top, no taskbar entry.
  - Cursor-polled click-through and hover (`pet:rects`, `pet:hover-rects`), and dragging the sprite (`app-region: drag` becomes `start_dragging`, plus `pet:moving`).
  - `pet:resize`, `pet:config` with the active model, `pet:focus`.
  - The default WSL distro's bridge (`wsl.exe … ccpet-bridge`, JSON lines), `send` / `onMsg` / `onBridge`.
  - Done = the pet draws, shows WSL sessions, chats, can be dragged and clicked through.
- **M2 shell.**
  - Tray menu, summon hotkey and Ctrl+Alt+1…9, single instance, autostart.
  - Settings (`settings.json` in `%APPDATA%\Claude Pet`, the same file Electron uses), `window.json` anchor and placement, keep-on-top and off-screen rescue.
  - Notifications, clipboard, URL opening, folder picker, confirmation dialogs (hooks diff).
- **M3 Windows host.**
  - `ccpet-core`'s bridge runs in-process (mailbox-only, HTTP hooks on 47821, named-pipe PTY).
  - Merge and routing of several hosts (`merge.ts`), message queue, desktop registry, `desktopSend` / `focusWindow` (PowerShell scripts as in TS), open in terminal, PowerShell profile, connections panel, diagnostics.
- **M4.** Several WSL distros, models (list, ZIP install, codex import, remove), update check, `pet-helper.exe` stable copy.
- **M5.**
  - Tauri NSIS installer, side-by-side checks, then the switch: Electron is removed and the version is bumped.
  - Measure installer size and memory against the table above.
