# 0.7.0: ccPet on Rust

**Goal:** the pet uses less memory and disk, and starts faster. It does the same things as 0.6.x: no feature changes, no new features until this is done.

## Starting point (measured 2026-11-18, 0.6.8)

| What | Now |
|---|---|
| Windows app (Electron, 4 processes) | 279 MB private memory, 409 MB working set |
| Installer / installed | 86 MB / 280 MB |
| WSL bridge (Node) | 105 MB |
| Mailbox waiter, one per open Claude Code session (Node, `pet-hook.mjs wait`) | ~65 MB each; 7 running = ~450 MB |
| Each hook event (Node start) | a new Node process per event |

The biggest waste is in WSL: one 65 MB Node process per session just to wait for a message, plus a Node process started for every hook event.

## Approach

Rewrite the parts that run in the background in Rust. Move the window to **Tauri** (Rust instead of Electron). The pet's interface (HTML, CSS, TypeScript in `ui/src/renderer`) stays: Tauri shows it in the system web view (WebView2 on Windows, WebKit on macOS and Linux), so it is not rewritten.

Rejected: rewriting the interface in a Rust UI library (egui, Slint, Iced). That means weeks of work to redraw what already works, and a transparent always-on-top sprite window is harder there than in a web view.

## Phases (each ends with tests passing and the pet working; committed one by one)

1. **`ccpet-hook` in Rust** (replaces `hook/pet-hook.mjs`, `hook/pet-statusline.mjs` and the `wait` of `pet-helper.exe`). One small binary per platform. Hook settings point at it; old settings keep working until re-applied. Expected: waiter ~65 MB → ~1–2 MB; a hook event starts in milliseconds. *2–3 days.*
2. **Bridge in Rust** (`daemon/src`, ~2,200 lines + tests): sessions, hooks over HTTP and the socket, mailbox, transcripts, limits, PTY send, hook installation with diffs and backups. Same JSON-lines protocol to the window, so the Electron app keeps working with it. No Node.js needed inside WSL any more. Expected: 105 MB → ~5–10 MB. *4–6 days.*
3. **Tauri instead of Electron** (`ui/src/main.ts` and friends, ~3,000 lines): window, tray, global hotkeys (incl. Ctrl+Alt+1…9), autostart, always-on-top over players and games, click-through, Windows desktop-app sending (`pet-helper.exe` stays as is), update check. Agent SDK chats (TypeScript only) go through the `claude` CLI instead. Expected: installer 86 MB → ~10–15 MB, memory ~280 MB → ~80–120 MB. **Risk:** transparent windows on Linux (WebKitGTK) are less reliable than in Electron. *5–8 days.*
4. **Builds and checks**: Windows, macOS (arm64, x64), Linux (deb, AppImage) in CI; the smoke test; measuring again against the table above; 0.7.0 release. *3–5 days.*

**Total: about 2.5–4 weeks.** Phases 1 and 2 already give most of the memory gain and can go out as 0.7.0-beta if wanted.

## Tools needed

- Rust in WSL (`rustup`, about 1.5 GB in the home folder): phases 1–2.
- Windows builds: either Visual Studio Build Tools (C++ workload, about 6 GB) for local builds and testing, or Windows builds only in GitHub Actions (nothing installed, but every Windows test waits for CI).

## Handoff (2026-11-18)

**Phase 1: done** (commit b73c091 on `v0.3-dev`, installed locally as 0.7.0-beta.1). `native/ccpet-hook`: events, `wait`, `statusline`, `--version`. `scripts/build-native.mjs` builds it into `build/hook/ccpet-hook`; the bridge picks it via `pickHook` (nodeCmd.ts) and offers upgrading 0.6 hook commands (`upgrade` flag → dialog in main.ts). Hook tests run against it with `PET_HOOK_BIN=<binary>`.

**Phase 2: in progress, compiles, 44 core tests + a smoke run pass (not committed yet).** `native/ccpet-core/src/`: `types`, `i18n`, `map_event`, `store`, `mailbox`, `soft_stop`, `summary`, `paths`, `transcript`, `usage`, `install` (hooks, waiter, statusLine, diffs, `.bak`; native `ccpet-hook` only, 0.6 Node entries are recognised and replaced), `procinfo`, `pty_send`, `adopt`, `hook_socket`, `hook_http` (tiny std HTTP/1.1 server), `bridge` (commands, hooks, permissions/questions, mailbox send, PTY send, interrupt watch, usage push; `Runner` trait for everything that starts `claude`). `native/ccpet-bridge/src/main.rs`: stdin/stdout JSON lines, socket, HTTP receiver, `hub.json`, 1.5 s tick, transcript adoption, copies `ccpet-hook` to `~/.claude-pet/bin`. Release binary ~0.9 MB; smoke-tested with an isolated `HOME` (hook over the socket → snapshot, `hooks` plan, `usage`, exit on stdin EOF).

**Still to do in phase 2:** (1) the `claude` stream-json client behind `Runner` (new chats, resume fallback with `resumeCwd`, `/btw`, models, `setModel`, permission policy, and `get_usage` for `LiveSource` on the ring click) — until then `NoRunner` answers "not available in the Rust bridge yet" and the live ring query is off (the statusLine file still feeds it); (2) switch the app to the binary: `ui/src/bridgeLaunch.ts` still runs `bridge.cjs` with Node, `scripts/build-native.mjs` builds only `ccpet-hook`, the installer must ship `ccpet-bridge`; (3) port tests of `bridge.test.ts` that the 6 Rust bridge tests do not cover yet (queueing, `end`/`dismiss` of live processes, `term-mark`, history re-read timing); (4) SIGTERM does not remove `hook.sock` (a stale socket is replaced on the next start); `source` of a waiter (`?src=`) is not stored yet; soft stop (Windows host only) is not wired into the Rust bridge. The Windows host (`ui/src/hub/windowsHost.ts`) keeps the TS modules until phase 3.

**Build notes.** WSL has no C compiler and no sudo: build with Windows' cargo from WSL:
`cmd.exe /c "cd /d C:\ClaudePet-v2\native && set CARGO_TARGET_DIR=%LOCALAPPDATA%\ccpet-target&& %USERPROFILE%\.cargo\bin\cargo.exe build --release --target x86_64-unknown-linux-musl"`
(rust-lld + musl, see `native/.cargo/config.toml`). Run the test binaries from WSL (they land under `%LOCALAPPDATA%\ccpet-target\x86_64-unknown-linux-musl\release`). JS: `node node_modules/vitest/vitest.mjs run`, `node node_modules/typescript/bin/tsc --noEmit -p .` (3 old loadPet.test errors are known). Installer: `PATH=$HOME/.local/node/bin:$PATH npm run dist`.
