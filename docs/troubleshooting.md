# Диагностика

Журнал приложения: `%APPDATA%\Claude Pet\pet.log`.

## Питомец пишет «Жду Claude Code…» и не видит сессий
- Подключены ли хуки? Трей → «Подключить хуки Claude Code…». Без них события не приходят.
- Сессия, запущенная **до** подключения хуков, появится после первого события в ней (например, после следующего сообщения).
- Закрыт ли мост? Если в чате «Нет связи с Claude Code в WSL», смотрите `pet.log`.

## «В WSL не найден Node.js» / нет связи с WSL
Мосту нужен Node.js в WSL: `~/.local/node/bin/node` или любой `node` в `PATH` (проверено на Node 22). Проверьте в WSL: `command -v node`.

## Обычная команда `claude` не идёт через питомца
- Откройте **новое** окно WSL после установки интеграции; проверьте `type claude`: должна быть функция.
- Обёртка не включается намеренно: вне терминала (скрипты, пайпы), для `-p`, `--help`, `--version`, `--bg`, подкоманд (`mcp`, `update`, …), внутри самого Claude Code и при `CLAUDE_PET_BYPASS=1`.
- Нужен `python3` в WSL (`command -v python3`) и сам `claude`.
- Включить заново/отключить: `bash …/resources/scripts/install-shell-integration.sh` и `--uninstall`.

## При отправке из питомца появляется предупреждение «открыта в терминале»
Это сессия без обёртки: сообщение пойдёт запасным путём SDK (второй процесс), в открытом терминале ответ не появится. Запускайте `claude` через интеграцию или `pet-claude.py`.

## Сессия Windows, десктопа или VS Code не видна
- «Настройки → Подключения → Скопировать отчёт»: в отчёте видно, подключены ли хуки и когда пришло последнее событие от Claude Code.
- Новая сессия появляется сразу при старте (её сообщает ожидатель `pet-helper.exe wait`). Сессия, запущенная до подключения хуков, появится после своего следующего сообщения.
- Начиная с 0.5.0 хуки ссылаются на копию `%LOCALAPPDATA%\ccPet\bin\pet-helper.exe`, а не на папку установки (файл занят, пока живут сессии, и мешал бы обновлению). После обновления питомец предлагает обновить пути: примите предложение.

## Лимиты не приходят от Windows-сессий
- Подключите «лимиты через статус-строку» для Windows в «Подключениях». Без Git Bash Claude Code запускает статус-строку через PowerShell; в 0.5.0 команда в кавычках там не работала — после обновления примите предложение обновить строку.
- Лимиты появляются после первого ответа модели в Windows-терминале (проверено). Запускают ли статус-строку десктоп и VS Code, пока не проверено.

## `claude -p` не завершается
Исправлено в 0.5.0: ожидатель сообщений больше не запускается в разовых `claude -p` (до этого они ждали его, пока работал питомец). Обновите питомца и примите обновление хуков.

## Горячая клавиша Ctrl+Alt+P не работает
Её мог занять другой процесс: при запуске питомец показывает уведомление «Горячая клавиша … недоступна». Значок в трее по-прежнему показывает/скрывает окно.

## Лимиты «недоступны»
Панель пишет причину. Частые: нужен вход claude.ai с подпиской Pro/Max (для API-ключа лимитов нет); эта версия Claude Code не поддерживает экспериментальный метод; запрос ещё идёт; сбой запроса (тогда показываются сохранённые данные с пометкой «устарели» и временем последнего успеха).
Регулярного опроса нет: цифры приходят из строки состояния Claude Code («Настройки → Подключения → лимиты через статус-строку») и по клику на кольцо. Полностью отключить запрос по клику: переменная окружения `CLAUDE_PET_LIVE_USAGE=0` для моста.

## Не устанавливается модель
Панель пишет причину. Допустимо: `pet.json`, лист спрайтов `.webp`/`.png` ровно 1536×1872, `tweaks.json`, текстовые README/LICENSE; без папок, ссылок, скриптов и исполняемых файлов. Модель с уже занятым идентификатором не заменяется: сначала удалите старую.

## Windows SmartScreen предупреждает об установщике
Установщик не подписан сертификатом: «Подробнее» → «Выполнить в любом случае». Контрольные суммы указаны в описании релиза.

## Сбросить настройки
Закройте питомца и удалите `%APPDATA%\Claude Pet\settings.json` (модели из `models\` останутся). Цвета можно сбросить кнопкой в настройках.
