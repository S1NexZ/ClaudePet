# Changelog

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии по [SemVer](https://semver.org/lang/ru/).

## [Не выпущено] — 0.7.0
### Добавлено
- **Плагин ccPet для Claude Code** (`/plugin install ccpet --marketplace S1NexZ/ccPet`). Это mod, который работает внутри Claude Code: в терминале, во вкладке Code приложения Claude и в VS Code. Сообщения из питомца он отправляет штатным `$.prompt.submit` как ваши собственные: без обёртки терминала и без ввода в окно приложения (то есть без обеих «серых зон»). Если Claude занят, сообщение само ждёт конца хода. Лимиты плана он берёт из Claude Code (`session.measure`) и пишет в файл, который читает кольцо питомца, без запросов через Agent SDK. Других действий у него нет: `claude plugin validate` показывает ровно три события и короткий список вызовов. Проверено вживую на Claude Code 2.1.327: сообщение из «почтового ящика» пришло как запрос пользователя, Claude ответил.
- «Почтовый ящик» питомца отличает плагин (`via=mod`): у сессии с плагином старый фоновый хук-ожидатель уступает ему место, сообщения больше не приходят бледной вставкой. В приложении Claude сообщение для такой сессии не вводится в окно.
- Пункт меню трея «Плагин ccPet для Claude Code…» с командой установки.

## [0.6.6] — 2026-11-18
### Безопасность
- **Открытие терминала больше не зависит от имени папки и текста сообщения.** Windows Terminal режет свою командную строку по каждой `;` (даже в кавычках, проверено), а `cmd.exe` выполняет `& | ^` в аргументах без пробелов. Папка вроде `C:\x&calc` или первое сообщение «почини тесты; потом закоммить» ломали запуск или могли выполнить лишнюю команду. Теперь папка Windows-сессии передаётся как рабочая папка процесса (`-d .`), а скрипт для WSL — целиком в base64. Это же чинит «Открыть в терминале» для WSL-сессий: прежняя команда содержала `; exit 0` и Windows Terminal разрезал её.
- Окно питомца не открывает новых окон и не переходит по ссылкам (защита на будущее: ссылок в чате нет).
- Токен приёмника хуков сравнивается за постоянное время.

### Изменено (правила Anthropic)
- **Запрос лимитов через Agent SDK — только по вашему клику.** По правилам Anthropic сторонние программы на Agent SDK должны использовать API-ключ, а не вход по подписке. Поэтому питомец больше не делает такой запрос сам при запуске; обновить цифры можно кликом по кольцу. Кольцо по-прежнему питается и строкой состояния Claude Code. Предупреждение при включении SDK теперь прямо называет это правило.
- **Сообщения из очереди и `/at` не управляют окном приложения Claude.** Они уходят, когда вас может не быть за компьютером, поэтому доставляются через хук, без вставки в окно и без перехвата фокуса (например, у полноэкранной игры). Сессии без связи с питомцем такие сообщения не получают: вместо диалога посреди ночи в чате появится заметка с текстом.

### Исправлено
- Вопрос Claude в питомце пропадает, когда Claude Code перестал ждать ответа (сессию закрыли): в 0.6.5 это работало только в тестах, мосты WSL и Windows не передавали сигнал отмены.
- Убран неиспользуемый код (`placeWindow`, `parentPid`).

### Изменено
- **Встроенный питомец называется «cPet».** Набор называет себя «Claude娘 (Claude-maiden)», а правила Anthropic о товарных знаках не разрешают использовать «Claude» в названиях функций чужих программ. Файлы набора не менялись, id `claude-maiden` прежний, выбранная модель у всех сохраняется.

## [0.6.5] — 2026-11-18
### Добавлено
- **Ответы на вопросы Claude прямо в питомце.** Когда Claude задаёт вопрос с вариантами (инструмент AskUserQuestion), питомец показывает его с кнопками-вариантами. Поддерживаются несколько вопросов подряд и выбор нескольких вариантов. Свой ответ можно напечатать в поле ввода. Кнопка «В терминале» оставляет вопрос терминалу или приложению. Ответ уходит через хук PermissionRequest (проверено на Claude Code 2.1.327). Ответили в терминале — вопрос в питомце пропадает. Закрыли сессию — тоже.
- **Сводка после ответа.** Если ход Claude изменил файлы, в чате питомца после ответа появляется карточка: сколько файлов, +/− строк по каждому, сколько заняло времени и сколько токенов ответа.
- **Очередь сообщений.** Пока Claude работает, поле ввода не блокируется: сообщение встаёт в очередь и уходит, когда ход закончится. Очередь видна под чатом, лишнее убирается крестиком. Команда `/at 23:30 текст` отправит сообщение в указанное время, `/at reset текст` — через минуту после сброса 5-часового лимита. Очередь сохраняется на диск и переживает перезапуск питомца.
- **Реакции питомца.** Тесты прошли или сделан коммит — питомец радуется (прыжок и взмах рукой). Тесты упали — грустит. Реакция длится около 2,5 с, запрос разрешения её прерывает. Для этого хуки слушают новое событие `PostToolUseFailure`.

- **Поддержать проект.** ccPet остаётся бесплатным. В меню трея появился пункт «Поддержать проект ❤» (Boosty), в README — раздел о поддержке (Boosty и Ko-fi), на GitHub — кнопка Sponsor. Никаких всплывающих окон и напоминаний.

### Изменено
- Хуки обновляются (питомец покажет изменения в settings.json): добавлены `PostToolUseFailure` и отдельная группа PermissionRequest только для вопросов Claude (таймаут 10 минут). Разрешения на инструменты по-прежнему отвечаются в питомце только если вы это включили.

## [0.6.4] — 2026-11-18
### Исправлено
- **Отправка в чат приложения Claude снова идёт как ваше сообщение, а не бледной вставкой через хук.** Если окно приложения было свёрнуто, оно не перерисовывалось: текст не попадал в поле (mismatch), кнопка «Отправить» не появлялась (no-send). Теперь окно на время ввода невидимо разворачивается без активации и сворачивается обратно. Флаг прозрачности, оставшийся от прерванной попытки (из-за него окно приложения рисовалось «призраком»), снимается автоматически.
- **Питомец больше не пропадает под полноэкранными плеерами.** Плеер мог снять с окна флаг «поверх всех», а Electron считал флаг ещё установленным и не ставил его заново. Теперь флаг переустанавливается каждые 2 с, и питомец продолжает рисоваться, когда его перекрыли. На macOS и Linux используется самый высокий уровень «поверх всех». Игры в эксклюзивном полноэкранном режиме перекрыть нельзя никакому обычному окну: используйте режим «оконный без рамки».
- **macOS: «Приложение повреждено».** Сборка не была подписана вовсе, и Apple silicon её не запускал. Теперь приложение подписывается ad-hoc при сборке (подпись проверяется в CI).
- **Linux: AppImage на Ubuntu 24.04+ падал при запуске** из-за песочницы Chromium. Встроенный запускатель оставляет песочницу там, где она работает (.deb), и выключает её там, где система её запрещает (AppImage). CI теперь запускает AppImage и установленный .deb так, как это делает пользователь.

## [0.6.3] — 2026-11-17
### Изменено
- **Отправка в чат приложения Claude стала фоновой.** Питомец ждёт паузы в работе клавиатуры и мыши (0,7 с), делает окно приложения на время операции полностью прозрачным и забирает фокус только на вставку текста: на замере 118–147 мс, после чего фокус сразу возвращается окну, в котором вы были. Кнопку «Отправить» он нажимает уже в фоне. Сообщение в чате настоящее, ваше. Прозрачность снимается в любом случае: при ошибке, по таймауту и при следующем запуске питомца. Окна, которые рисуют себя с попиксельной прозрачностью, не трогаются: отправка тогда просто не прячется. Попытка печатать в окно вообще без фокуса не работает: Chromium не принимает ввод в неактивное окно (проверено).

## [0.6.2] — 2026-11-17
### Изменено
- **`/model` и `/btw` работают без Agent SDK** в сессиях с терминальной обёрткой: питомец печатает строку в тот же терминал (`/model <имя>`, `/btw <вопрос>`), а выполняет её сам Claude Code. `/model` без имени показывает список псевдонимов (default, opus, sonnet, haiku, opusplan) и по выбору печатает команду. `/btw` пропускается и во время работы Claude. Для сессий без обёртки и для новых чатов остаётся прежний путь через SDK (если он включён).

### Исправлено
- **Питомец больше не пропадает с экрана.** Каждые 5 с он заново ставится поверх всех окон (полноэкранные приложения, игры и видеоплееры могли опустить его под себя; фокус при этом не забирается). Если падает процесс отрисовки или GPU, окно оставалось прозрачным и пустым: теперь это пишется в журнал и питомец рисуется заново. После отключения монитора или смены разрешения питомец, оказавшийся вне экранов, возвращается рядом с прежним местом.
- **Переписка читается с конца файла**, а не целиком: у долгих сессий файл достигает десятков мегабайт, и мост перечитывал его дважды на каждое сообщение (на файле 80 МБ около 0,85 с и 80 МБ памяти на каждое чтение; теперь около 15 мс). Результат тот же.
- Кнопки «Разрешить / Отклонить» в питомце пропадают сразу, если вы ответили на запрос разрешения в самом терминале или приложении (раньше висели до 30 с). Завершение параллельно работавшего другого инструмента их не снимает.
- Запросы состояния подключений к мосту (хуки, статус-строка) больше не путают ответы, когда их несколько подряд: раньше второй запрос затирал ожидание первого, и тот получал «нет ответа» через 4 с.
- Испорченная %-последовательность в адресе запроса к приёмнику хуков больше не может уронить процесс (раньше исключение вылетало из обработчика).
- Сессия, впервые увиденная без папки, получает папку и имя проекта из следующего события.
- На Linux и macOS тексты меню трея и диалогов больше не говорят о WSL и Windows; убран мёртвый код.
- **Сообщение из питомца набиралось в терминальную сессию дважды** (текст приходил в Claude удвоенным). Команда чата уходила в мост и через `send`, и через запасной `?? toBridge`, потому что `send` ничего не возвращает. Теперь команда уходит один раз. Ошибка была в коде с 0.5.0 (многодистрибутивный режим).

## [0.6.1] — 2026-11-17
### Изменено
- **Отправка в чат приложения Claude стала быстрой и почти незаметной** (около секунды вместо нескольких). ## [0.6.0] — 2026-11-17
### Добавлено
- **Linux и macOS (бета).** Мост Claude Code запускается на самом компьютере внутри самого приложения (Electron как Node), WSL не нужен. Сборки: `ccPet-<версия>-linux-x64.AppImage` и `.deb`, `ccPet-<версия>-mac-<x64|arm64>.dmg` и `.zip` (не подписаны). Что сделано: переносимые сведения о процессах (`/proc` в Linux, `ps` в macOS) для терминалов и одноразовых запусков `claude -p`; хуки и строка состояния вызывают то же приложение с `ELECTRON_RUN_AS_NODE`, а скрипты хуков копируются в `~/.claude-pet/bin` (путь AppImage меняется при каждом запуске); открытие и поднятие терминала (gnome-terminal, konsole, xfce4-terminal, kitty, alacritty, xterm; `wmctrl`/`xdotool`; Terminal.app через osascript); автозапуск Linux через `~/.config/autostart`; обёртка `claude` для zsh (`~/.zshrc`); на macOS питомец живёт без значка в Dock, на Linux окно работает через X11/XWayland. Windows-части (WSL, PowerShell, приложение Claude) на этих системах скрыты.
- **Команды в чате.** Строка ввода показывает меню при вводе `/` (стрелки, Tab, Enter). Команды питомца: `/model`, `/btw`, `/stop`, `/new`, `/end`, `/sessions`, `/terminal`, `/usage`, `/settings`, `/help`. Команды Claude Code (`/compact`, `/clear`, `/cost`, `/context`, `/status`, `/memory`, `/init`, `/review`, `/resume`) печатаются в терминал сессии как есть, если у сессии есть связь с обёрткой; иначе питомец объясняет, что команда там не сработает. Незнакомые `/слова` (скиллы, свои команды) уходят как набраны.
- **GitHub Actions**: тесты на Ubuntu и macOS, сборка Linux/macOS пакетов, запуск собранного приложения под Xvfb с проверкой, что мост подключился.

### Изменено
- Значок приложения теперь из встроенной модели по умолчанию (Claude娘), 512×512; прежний значок остался от удалённого Clawd.

### Исправлено
- Тесты, которым нужна локальная папка `sprites/` (её нет в репозитории), пропускаются, если её нет.

## [0.5.2] — 2026-11-17
### Добавлено
- **Сообщение из питомца в чат приложения Claude отправляется как обычное сообщение пользователя** («Вы сказали: …»), а не бледной вставкой хука. Питомец открывает чат ссылкой, вводит текст в поле через UI Automation и нажимает «Отправить»; перед этим проверяет, что открыт нужный чат и что текст принят. Если поле не найдено или чат занят, сообщение уходит через хук, и в чате питомца появляется пометка. Переключатель в «Настройки → Подключения».
- **Новый чат в приложении Claude** (третий вариант в «Где запускать новые чаты», нужна папка Windows): приложение само подставляет текст, питомец нажимает «Отправить». Вопрос приложения «Доверять этой папке?» питомец никогда не нажимает: он сообщает, что решать вам.
- Переименование, архивирование и удаление чата в приложении видны в питомце сразу (за папкой чатов следит наблюдатель; раньше до 5 секунд).

### Изменено
- **Новый вид: «Чистая» и «Рейка сбоку».** Статус и лимит слиты в один значок: цветная точка статуса внутри дуги лимита (акцентный цвет), рядом одно короткое слово («Готов», «Запуск», «Разрешить?»). Остров всегда виден; при смене статуса слово прокручивается вверх, а остров плавно меняет ширину только вправо, кольцо остаётся на месте под питомцем (проверено в ru, en, zh). Нажатие на остров показывает название сессии и время, нажатие на дугу открывает панель лимитов. Кнопки «Чат», «Настройки» и «Сессии» стали колонкой круглых кнопок справа от питомца: остров под ним не сдвигается при наведении.
- Настройки в том же стиле: пилюльные вкладки, засечные заголовки секций, живой предпросмотр значка на вкладке «Цвета».

### Исправлено
- **Пурпурный контур у моделей.** У многих паков края силуэта окрашены остатком цветового ключа, которым вырезали фон (у yorha-sit-2b, temusan-miku и shy-miku пурпурными были 66–84% краевых пикселей, а ореол шириной 2–3 px и тёмно-фиолетовая полупрозрачная кайма мерцали от кадра к кадру в анимациях). Питомец теперь при загрузке модели берёт для краевых пикселей цвет соседей изнутри (прозрачность сохраняется), тёмную фиолетовую кайму делает серой той же яркости и убирает одиночные бледные пикселы; пурпурные модели и нарисованные автором непрозрачные контуры не трогаются. Отключается в `tweaks.json` модели: `{"spill": false}`.

### Не вошло
- «Открыть в приложении» для терминальных сессий: ссылка `code/resume` не импортирует сессии из WSL.

## [0.5.1] — 2026-11-17
### Добавлено
- **Проверка обновлений** раз в сутки (публичный адрес релизов GitHub, без данных о вас): уведомление и пункт в меню трея, страница релиза открывается по клику. Сам ничего не скачивает; выключается в меню трея.

### Исправлено
- **Лимиты больше не откатываются назад.** Другие сессии перерисовывали статус-строку со старыми цифрами, и они перетирали свежие. Теперь внутри одного окна лимита (одно время сброса) процент может только расти; новое окно (более позднее время сброса) заменяет старое. Работает и при записи статус-строки (WSL и Windows), и при объединении источников.
- **Статус-строка Windows не работала без Git Bash** (Claude Code тогда запускает её через PowerShell, а путь в кавычках там синтаксическая ошибка). Теперь путь записывается без кавычек и с прямыми слэшами; при запуске питомец предложит обновить строку.
- Первое сообщение нового Windows-чата больше не может попасть в уже открытую сессию в той же папке.
- Профиль PowerShell пишется в UTF-8 с BOM (или остаётся UTF-16): Windows PowerShell 5.1 читал путь с кириллицей в ANSI и обёртка ломалась. Профиль в ANSI питомец не меняет и просит добавить строку вручную.
- Короткий путь `pet-helper.exe` для путей с пробелами вычислялся неверно.
- Ожидатели ждут недоступного питомца не дольше 10 минут (не копятся), один повторный запрос на тайм-аут; `-p` в тексте подсказки или у постороннего процесса больше не принимается за `claude -p`.
- Без `pet-helper.exe` первое сообщение нового Windows-чата не теряется: оно копируется в буфер с объяснением.
- Учёт событий и сессий при нескольких дистрибутивах WSL; лишние временные файлы статус-строки.

### Изменено
- **Меньше нагрузки в покое**, внешне без изменений: цикл отрисовки спит до следующего кадра спрайта, а не работает 60 раз в секунду; свечение точки статуса — CSS-анимация прозрачности (без перерисовки); таймер анимаций GSAP переходит на 15 Гц, когда идёт только «дыхание». Замер: около 3,4% всех ядер → 0,9–1,6%.
- **Цвет дуги лимитов** всегда ваш (акцентный цвет из «Настройки → Цвета»), без автоматического жёлтого и красного; исчерпанный лимит по-прежнему «дышит».
- **pet-helper.exe запускается из постоянной копии** `%LOCALAPPDATA%\ccPet\bin`: он работает, пока живы сессии, и раньше мешал установщику заменить файлы. При первом запуске питомец предложит обновить пути в подключениях.
- Подписи в статус-строке Claude Code не зависят от языка: `5h 23% · 7d 77%` (раньше «5ч · нед»).

## [0.5.0] — 2026-11-17
Главное: десктопное приложение Claude и Windows работают как «родные» сессии.

### Десктоп Claude
- Сессии десктопа показываются под **названиями чатов** (вместо `scratch-…`), архивные чаты скрыты. Из файла сессий десктопа читаются только id, название и флаг архива.
- **«Открыть»** для такой сессии открывает именно этот чат в приложении Claude (ссылка `claude://code/continue`) и поднимает окно, без второго процесса `claude`.
- **«Стоп»** работает для десктопа, IDE и обычных Windows-терминалов: Claude останавливается после текущего шага (официальный ответ хука `continue: false`).

### Windows
- **Лимиты из Windows-сессий:** статус-строка `pet-helper.exe statusline` (ваша собственная строка сохраняется); данные WSL и Windows объединяются, показываются самые свежие.
- **Обёртка `claude` в профиле PowerShell ставится кнопкой** в «Подключениях» (изменения показываются, копия `.bak`, отмена одной кнопкой); предупреждение, если политика выполнения не даёт запускать профиль.
- **«Открыть в терминале»** поднимает вкладку самой сессии (для сессий через обёртку) вместо клона.
- **Новые чаты можно запускать в Windows** («Подключения → Где запускать новые чаты»); первое сообщение вводится в сессию, когда она появится.
- Новые Windows-сессии (в том числе VS Code) видны сразу при старте, с меткой источника; сессии не теряются при перезапуске питомца.
- При запуске питомец предлагает обновить устаревшие хуки Windows (с показом изменений).

### Подключения и диагностика
- Для каждого подключения видно время последнего события от Claude Code.
- Кнопка **«Скопировать отчёт»**: все проверки подключений одним текстом, без имени пользователя и токенов.

### Исправлено
- Пока питомец работал, разовые запуски `claude -p "…"` (Windows и WSL) не завершались: их держал ожидатель сообщений. Теперь он в таких запусках не стартует.
- Панель сессий сворачивается вместе с чатом.

### Изменено
- Встроенная модель **Clawd удалена** (это маскот Anthropic). По умолчанию теперь **Claude娘 (Claude-maiden)**; если у вас был выбран Clawd, питомец переключится на неё сам. Clawd можно поставить вручную как свою модель.
- Кружок статуса и кольцо лимитов одного размера и стоят ровно при любом масштабе экрана.

Подключение строки состояния — в «Настройки → Подключения → лимиты через статус-строку» (с diff и копией файла; ваша собственная строка не теряется: питомец оборачивает её и при отключении возвращает как была).
